# API Specification

> REST standards · versioning · auth · errors · OpenAPI

## 1. Purpose

Defines the external interface contract for the platform. The authoritative machine-readable
artifact is the **OpenAPI 3.1** document generated by NestJS (`/v1/openapi.json`) — this document is
the human-readable companion.

## 2. REST Standards

- Base URL: `/api/v1`
- JSON only (requests and responses). `Content-Type: application/json`.
- Resource-oriented, plural nouns: `/customers`, `/invoices`.
- HTTP verbs meaningful:
  - `GET` collection / single
  - `POST` create or custom action (endpoint suffix)
  - `PATCH` partial update
  - `DELETE` delete (soft-delete default)
- Nested resources only one level deep: `/customers/{id}/messages`.
- Read models are immutable snapshots; write via commands.

### 2.1 Consistent envelope

```json
{
  "data": { ... },
  "meta": { "requestId": "..." , "pagination": { ... } }
}
```

Errors use the standard error contract (see §8).

## 3. Versioning

- Path segment: `/api/v1/...`
- Deprecation policy: breaking changes go to a new major (v1 → v2) announced ≥ 6 months prior.
- `Deprecation` header carries sunset date.
- Breaking changes within v1 (fields added, non-breaking) are additive.

## 4. Pagination

- Offset + limit, `limit` default 20, max 100; `page` default 1.
- Response: `meta.pagination = { page, limit, total, pages }`.
- Response header `X-Total-Count` for compatibility.
- For time-series endpoints, cursor pagination `cursor=` on `created_at*id`.

## 5. Filtering & sorting

- Query params: `?status=paid&customer_id=...`
- Range filters: `created_at_gte`, `created_at_lt` (ISO8601).
- Sorting: `sort=-created_at` (minus = desc), multi: `sort=-priority,created_at`.

## 6. Authentication & Authorization

- Authentication: **OAuth2 / OIDC** via Keycloak; the client exchanges code for token.
- Transport: `Authorization: Bearer <access>`.
- Scopes map to RBAC roles: `role:owner`, `role:admin`, `role:manager`, `role:agent`, `role:viewer`
  (hierarchical: owner > admin > manager > agent > viewer).
- Token expiry: access 15 min, refresh 7 days (rotate on use).
- Every request is tenancy-scoped from the token claims (`org_id`, `request_id`).
- Enforcement: `JwtAuthGuard` (RS256/JWKS) → `TenancyGuard` (membership) → `RolesGuard` (role
  requirements) on protected routes; entity-level checks in application services.
- See [SECURITY_SPEC](./SECURITY_SPEC.md) for flows and JWT validation requirements.

## 7. Validation

- Request bodies validated with `class-validator` + `class-transformer`, whitelist unknown
  properties out by default.
- DTO naming `<Verb><Resource>Dto` (`CreateInvoiceDto`, `UpdateCustomerDto`).
- Validation errors: `400` with field-level `errors[]`.
- Idempotency: `Idempotency-Key` header for mutating ops (POST invoice, create order).

## 8. Rate Limiting

- Per-user: bursts allowed 100 req/min/user with `X-RateLimit` headers.
- AI endpoints: per-org monthly token budget enforced via AI gateway (§ AI spec).
- When the limit is hit, return early `429` with `Retry-After` header.

## 9. Error contract

```json
{
  "error": {
    "code": "INVOICE_NOT_FOUND",
    "message": "Invoice 123 not found for this organization.",
    "status": 404,
    "details": {},
    "path": "/api/v1/invoices/123",
    "timestamp": "2026-08-02T10:00:00Z",
    "requestId": "cd93..."
  }
}
```

Common codes:

| HTTP | Code                   | Meaning                                                        |
| ---- | ---------------------- | -------------------------------------------------------------- |
| 400  | `VALIDATION_ERROR`     | Malformed payload                                              |
| 401  | `UNAUTHORIZED`         | Missing/invalid token                                          |
| 403  | `FORBIDDEN`            | Role/tenant denied                                             |
| 404  | `*_NOT_FOUND`          | Resource absent                                                |
| 409  | `CONFLICT`             | State conflict                                                 |
| 413  | `PAYLOAD_TOO_LARGE`    | Upload over `MAX_UPLOAD_SIZE_MB`                               |
| 422  | `VALIDATION_FAILED`    | DTO validation failed                                          |
| 422  | `UNSUPPORTED_DOCUMENT` | Unsupported format or scanned PDF (no text layer; OCR pending) |
| 429  | `TOO_MANY_REQUESTS`    | Rate limit                                                     |
| 503  | `STORAGE_UNAVAILABLE`  | Object storage not configured/unreachable                      |
| 500  | `INTERNAL_ERROR`       | Unexpected                                                     |

## 10. OpenAPI

- Generated from NestJS decorators at `apps/backend` `GET /api/v1/openapi.json`.
- Conventions: server URL, global `BearerAuth`, `tags` matching module names.
- Published release artifact: `docs/api/openapi.yaml` snapshot per release.

### 11.3 Presigned storage upload (MinIO)

Opaque org-scoped object keys: `{org_id}/{uuid}`. The client PUTs the file directly to MinIO; the
original filename is returned as metadata only.

```http
POST /api/v1/storage/uploads/presign
Authorization: Bearer <jwt>
Content-Type: application/json

{
  "filename": "invoice.pdf",
  "contentType": "application/pdf"
}
```

```json
200 {
  "data": {
    "uploadUrl": "http://localhost:9000/smb-copilot/org-1/7b02e1b2-...?X-Amz-Signature=...",
    "objectKey": "org-1/7b02e1b2-...",
    "filename": "invoice.pdf",
    "contentType": "application/pdf",
    "expiresIn": 3600
  },
  "meta": { "requestId": "..." }
}
```

### 11.4 Document ingestion

Upload flow: presign → PUT to MinIO → register → ingest.

```http
POST /api/v1/documents
Authorization: Bearer <jwt>
Content-Type: application/json

{
  "fileName": "invoice.pdf",
  "contentType": "application/pdf",
  "sizeBytes": 20480,
  "storageKey": "org-1/7b02e1b2-..."
}
```

```json
201 {
  "data": {
    "id": "doc-1",
    "fileName": "invoice.pdf",
    "contentType": "application/pdf",
    "sizeBytes": 20480,
    "storageKey": "org-1/7b02e1b2-...",
    "status": "PENDING"
  },
  "meta": { "requestId": "..." }
}
```

```http
POST /api/v1/documents/doc-1/ingest
Authorization: Bearer <jwt>
```

```json
200 {
  "data": {
    "id": "doc-1",
    "status": "INDEXED",
    "cleanTextKey": "org-1/doc-1/clean.txt"
  },
  "meta": { "requestId": "..." }
}
```

Status lifecycle: `PENDING → PROCESSING → INDEXED | FAILED`. Re-ingestion of an `INDEXED` document
returns `409 CONFLICT`. Scanned PDFs (no text layer) return `422 UNSUPPORTED_DOCUMENT` until OCR
lands. On completion the service publishes `document.ingested` to the domain event bus and queues an
embedding job.
